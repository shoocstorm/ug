# Session summary — 2026-07-25

11 commits on top of `fc94676`, plus the working tree.
9 files, roughly +10.6k / −2.5k — most of it `visualization.html` and the new
`tour.rs`.

Two threads run through the night. The first is **the guided tour**, taken from
"exists" to "usable". The second is **making the LLM features honest and fast** —
which turned out to be the same problem seen from two sides: a local model that
answers at 30 tokens/second punishes every wasted token, and a user who can't
see what the model was given can't tell a good answer from a fluent one.

---

## 1. The tour became something you'd actually watch

The planner was there; the experience wasn't. What changed, in rough order of
how much it mattered:

**Progressive start.** `StopScanner` pulls each finished `{…}` out of the
still-streaming `"stops": […]` array, binds it to a real node, and ships it as
`TourProgress::Drafted`. The camera starts flying on stop 1 while the guide is
still writing stop 4. Measured ~50% sooner to first stop; on a slow model it's
minutes.

**A narrated wait.** Planning reports phases — retrieving, reading code,
linking, briefing the guide, writing, assembling — over SSE (`POST /api/tour`
with `"stream": true`). The card shows a step checklist with real numbers
(`14 found · 6 ms`, `5 edges`), elapsed time, live token count and rate. The
CLI prints the same phases with an in-place token counter.

**Cinematic framing.** Four-ring lowlighting (`tourTier`): the current stop,
the rest of the route, its neighbours, then everything else at 3.5% opacity.
Route edges glow and carry particles; only stops keep labels. The camera flies
broadside to the direction of travel so the hop you just took stays visible,
and the finale pulls back to frame the whole route. Solo mode (`O`) hides
everything off-route entirely.

**A card you can live with.** Draggable (position persisted), translucent so
the graph reads through it, capped at 28vh so it stops swallowing the view.
Media-player transport — centred play/skip, speed control, `PLANNING` /
`PLAYING` state. Code and warnings moved behind header icons that only appear
when there's something to show.

**Provenance.** A JSON viewer (`{ }`) shows the plan the model produced, the
stops after binding, the candidate pack it chose from, the prompts it was
given, and its raw reply. The last five tours are saved per project and replay
without another model call.

## 2. Turning thinking off is worth ~60×

The tour was taking **ten minutes and never finishing**. The cause wasn't the
plan or the prompt: the model was spending 20k+ tokens deliberating before its
first useful character, and prompt instructions can't stop that — thinking
lives in the chat template.

`ChatConfig::extra_body` now carries the real switches
(`chat_template_kwargs.enable_thinking: false`, `reasoning_effort: "low"`), and
`ChatClient::post_chat` retries without them on a 4xx so a stricter provider
can't break. Same query, same model: **10+ min → 9.4 s**. `--think` opts back
in.

Supporting cuts, in the same spirit:

- **Completion budget**: the 1024-token chat default truncates a plan
  mid-string. Tours raise it to 32k, with a matching 900s timeout — raising
  tokens alone just trades truncation for a timeout.
- **JSON extraction that survives a reasoning preamble.** "First `{` to last
  `}`" breaks on prose containing braces. `top_level_objects()` scans
  string-aware balanced spans; `plan_score()` picks the one that looks like a
  plan.
- **Prompt and output slimming**: snippets 480→260 chars for the top 10
  candidates only, descriptions clipped to one line, narration capped at two
  sentences. Prompt went 10.8k → 6.9k chars.

## 3. The model got tools, and the user got to watch

`chat::ToolBox` + `run_tool_rounds` implement OpenAI function calling for chat
(on by default) and the tour (`research: true`, off by default). The schemas
come **straight from the MCP registry** — `mcp::tools::openai_tool_schemas()`
converts `tools/list` into `function` shape — so an agent over MCP and the
model behind `/api/chat` see one toolbox with one set of descriptions.
Execution reuses `agent_tools::run_tool` against the already-open store and
graph. Tool rounds run non-streaming (partial `tool_calls` deltas are the
ugliest corner of the wire format); only the final answer streams.

Every call is visible: name, arguments as sent, and the tool's verbatim
response — the same text the model was handed, each block copyable. Including
tool *errors*, which is how you watch a model pass a bad id, read the error and
correct itself.

**Why the model wasn't calling them.** The RAG system prompt said *"answer
using ONLY information present in those items"* — which reads as "don't go
looking", and the model obeyed. It now says the retrieved items are a starting
point, names when each tool earns its keep, and tells the model to **rewrite
the query in the codebase's vocabulary and search again** when the first pass
looks thin.

**Why its arguments were malformed.** `nodeId` is `oneOf: [string, array]`, and
union types are what smaller models fumble — they send
`"nodeId": "[\"function:…\"]"`, a JSON array encoded as a string.
`mcp::tools::normalize_args()` re-reads each argument against its own schema
and unwraps what the model quoted. Applied at all three entry points (chat,
MCP, `/api/tools/:tool`), because every client makes the same mistake.

`ug chat` now gets the same streaming and the same toolbox (`--no-tools`,
`--max-tool-rounds` to bound it).

## 4. Showing the machinery

**The chat setup inspector** (`GET /api/chat/config`) answers three questions
the UI otherwise hides: how context was retrieved, what the model was told, and
what it could call. Notably it corrects a common wrong guess — retrieval is
**not** semantic-only. It's hybrid dense+keyword seeds fused by Reciprocal Rank
Fusion, then Personalized PageRank over the graph, then a char-budgeted pack.
The panel names each stage, shows the live parameters, prints both halves of
the system prompt verbatim, and lists every tool with its JSON schema.

**The node panel** gained a Chunk tab — the text the node was actually embedded
as, parsed back into heading / description / signature / related names, which
is the honest answer to "why did semantic search match this?". Every tab now
states its source (`graph.json`, `vector store`, `working tree`), because the
panel mixes three and they disagree.

**The rest of the UI** caught up: markdown rendering for answers with clickable
`[#N]` citations, collapsible sources, Discover split into Search / Tour / Chat
sub-tabs, per-type node icons everywhere a type appears, a resizable details
panel, and a dark canvas that makes the graph read as luminous ink rather than
flat paper.

## 5. Two bugs found by asking "why doesn't this work?"

**`ug mcp install claude` produced an invisible skill.** It wrote
`~/.claude/rules/ug-mcp.md` with the frontmatter *stripped* — but Claude Code
discovers skills at `.claude/skills/<name>/SKILL.md`, and the frontmatter is
*how* it discovers them. Both wrong. Now written correctly, with the legacy
path cleaned up on install and uninstall. Verified by the skill appearing in a
live session's skill list — the install printing a path proves nothing.

**`UG_PROJECT` was derived from the installer's cwd**, so it often named a
directory that wasn't an indexed project (`native`). The MCP server is launched
by an editor from wherever it likes; cwd was never the right signal. It now
resolves active project → first indexed project → cwd, and says which and why.

## 6. When there's no model

Chat and part of the tour need an LLM. Two distinct failures, both now spoken
in plain words with a button that opens Settings (the model is editable at
runtime — "restart the server" was never the right advice):

- **Not configured** — *"Chat needs a language model… Nothing else here needs
  it: search, the catalog and the graph all work as they are."* The tour's
  version is honest that tours still run, just without narration.
- **Configured but unreachable** — the server classifies connect/timeout/404 as
  `kind: "llm_unreachable"`, and the UI says *"Nothing answered at
  http://127.0.0.1:8000/v1. Start your local model server, or point UltraGraph
  somewhere else."* instead of printing a transport error at someone who can't
  read it.

## Verification

205 Rust tests (up from 177), with new coverage for the incremental stop
scanner, JSON extraction through reasoning preambles, argument coercion, the
skill install paths, and `UG_PROJECT` precedence.

The UI was driven headless over CDP throughout — thirteen suites, ~200
assertions, run against a real `ug serve` and a real local model, not just
mocks. That mattered: an instant mock hides truncation, hides tool latency, and
hides the difference between "no tools" and "tools somewhere off-screen".

Two habits worth keeping:

- **Test against a slow endpoint.** Every speed problem this session was
  invisible under a mock.
- **When a model's behaviour looks wrong, read the prompt before the code.**
  Twice the "bug" was an instruction doing exactly what it said.
