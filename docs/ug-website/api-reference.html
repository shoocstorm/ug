--no-embed vs --no-ingest

Accepted by ug gen and ug update. They are commonly confused, and the difference decides whether ug analyze — statistics, diff_impact, blast radius — can be trusted after the run.

FlagWritten to the dbCurrent after the runAnswering from the previous ingest
--no-embed nodes, edges, facts and keyword statistics — everything except the vectors. No embedding model is loaded, which is most of a small run's wall clock. the graph.json tools and ug analyze: statistics, diff_impact, boundary_impact, blast radius search, chat — they miss the changed nodes until the vectors are backfilled
--no-ingest nothing at all — no nodes, no edges, no vectors; the db is never opened. Only graph.json is rebuilt. the graph.json tools only: find_symbols, file_outline, get_code, find_usages, context, shortest_path, project_overview everything the db backs — ug analyze statistics and blast radius as well as search, chat

ug ingest -n <project> catches the db up either way — it embeds only the nodes still owed a vector.

1.3.1 Wildcards

Wherever a symbol or file is named — find_symbols names, node types and file filters, file_outline paths, and the symbol arguments of get_code, find_usages, traverse and shortest_path — you can pass a shell-style pattern instead. One matcher serves the CLI, the HTTP API and the MCP tools, so a pattern behaves identically on all three.

SyntaxMatches
*any run of characters (not / in a path)
**any run of characters, / included (paths)
?exactly one character
[abc] [a-z]one character from the set or range
[!ab]one character not in the set
{a,b}either alternative, nestable
\*a literal *

Matching is case-insensitive and covers the whole name: auth* finds authorize, *auth* finds reauth. In paths, * stops at / while **/ crosses directories — and matches zero of them too, so src/**/*.rs finds src/main.rs. Quote patterns in a shell, or it expands them before ug sees them.

cli · one call instead of a loop
$ ug find_symbols 'handle_*'                          # every handler
$ ug find_symbols '*Controller' --node-type Class
$ ug find_symbols '*' --file-prefix 'src/auth/**' -k 100   # a whole subtree
$ ug file_outline 'src/**/*.{ts,tsx}' -k 40          # survey many files at once
$ ug find_usages  'validate_*'                        # blast radius of a family
$ ug traverse     'handle_*' -d inbound              # one merged walk

# and when the question is one symbol rather than a family:
$ ug context      processPayment                    # code + callers + tests + deps + docs

In the id-taking commands a name or pattern expands to at most 25 symbols; going over that cap is reported in the output, never silent. shortest_path needs each endpoint to match exactly one symbol, and lists the candidates when it doesn't.

1.9 Project Resolution & Active Project Fallback

Commands need to resolve a project name to read graph.json and/or write/load the OverGraph store (ugdb). The order varies by command group:

Resolution Order by Command Group

Command GroupResolution OrderNotes
gen, index, graph -n/--name → derive from input path Generate commands must use cwd when no -n and no project matches (they create a new project)
gen (no -i/--input) -n → active project → cwd basename Re-runs the resolved project from its recorded repo root; honors user's pinned active project
ingest -n → active project → cwd basename Reads graph.json and writes ugdb from the active project by default
Read commands
(search, traverse, chat, tour, query, graph_centrality, graph_cycles)		 -n → active project → cwd basename → most-recent Now consistent with gen/ingest
server, app, mcp -n → active project → cwd Always opens the active project
Any command with -i/--input -i wins Bypasses all project logic

The Scope Banner

Every project-scoped command prints the project it resolved to — and which link of the chain above produced it — as one line on stderr before it does any work:

▸ project ug · ~/Documents/project/ug · data ~/.ug/ug · [active project]

It goes to stderr, not stdout, so --json/-o output stays pipeable — ug find_symbols x --json | jq is unaffected. A command that resolves the same project twice (the agent tools read graph.json, then the ugdb beside it) prints one line, not two.

The […] label is the rule that fired: -n/--name, --db, -i/--input, input path, active project, current directory, legacy ./.ug/ugdb, or most recently updated project — the last being the one worth noticing, since it means the command answered from a project that has nothing to do with the current directory. Because ug hook captures the child's output into ~/.ug/<project>/hook.log, this line is also what makes a hook run auditable after the fact. Suppress it with --no-banner or UG_NO_BANNER=1.

default_read_db_path() Fallback Chain

When no -n/--name flag is provided, the store/db path resolves through:

1. active project's ~/.ug/<active>/ugdb ← honored first
2. cwd-basename ugdb (if exists)
3. legacy ~/.ug/ugdb ← deprecated path
4. most-recently-updated project's ugdb ← last resort
5. cwd-basename ugdb (always exists, may be empty)

This chain ensures that commands like ug search "query" or ug chat "what is X" run from an arbitrary directory will automatically pick the project the user previously pinned with ug active <name> rather than silently using the cwd or a random "most-recent" project.

3.3 context — the curated pack

Working on a symbol used to take four or five calls — read the source, find the callers, walk the dependencies, find the covering test, read the doc. context is that sequence as one call with one budget, and it is the first tool an agent should reach for when it is about to change something.

ParameterTypeDescription
nodeId (required)stringThe one symbol to build the pack around — a node id, an exact name, or a wildcard. Must resolve to exactly one symbol; an ambiguous name is an error listing the candidates, because a pack is a claim about one neighbourhood.
maxCharsintegerTotal budget for the pack. Default 12000, minimum 500.
includestring[]Keep only these roles. Omit for all five. ["caller","test"] is the edit-safety pair.

Every item carries the role that put it there — that label is the feature. A bundle of related symbols with no stated reason for each is a pile the caller has to re-derive; labelled, it can drop the half it does not need without a second call.

RoleWhat it isCarries
targetthe symbol itselfits doc comment + source, capped at half the budget
callerdirect (1-hop) inbound userssignature + the call-site lines
testtest symbols reaching it within 2 hopssignature + call sites
dependency1-hop outbound neighbourssignature only
docConcept nodes linked to itprose preview

Roles are filled in that order, which is a priority claim rather than a taxonomy: working on a symbol you need its body first, then who breaks if it changes, then what proves it still works, then what it leans on, then the prose. Lowering maxChars therefore sheds docs and dependencies before it sheds callers, and whatever did not fit is reported rather than silently dropped.

cli · one call instead of five
$ ug context processPayment
Context for Function processPayment  src/billing/payment.ts:88-146
1986 chars of 12000 budget · 3 caller, 2 test · not shown: 4 dependency

── callers (3) ──
- Function checkoutHandler  src/routes/checkout.ts:41-77
  this —Calls→ target
    58  const receipt = await processPayment(order, card);

── tests (2) ──
- Function declines_an_expired_card  tests/payment.test.ts:12-30
  test —Calls→ target

# the edit-safety half on its own
$ ug context processPayment --include caller --include test
# or over MCP
$ ug mcp call context '{"nodeId":"processPayment","maxChars":4000}'

Two classification rules keep the roles from overlapping. A test that calls the target is listed once, as a test — “who breaks” and “what re-verifies” are different questions, and the same node answering both would read as two callers. A Concept node pointing at the target is a doc, not a caller: prose that references a symbol is not code that breaks when it changes. Test detection shares one definition with the test_for preset, so context and analyze test_for can never disagree about what a test is.

maxChars is a budget, not a guarantee — assembly and rendering are separate steps, so the renderer's fixed overhead is charged as an estimate. At the default the pack lands under; at very small budgets it can run a couple of hundred characters over.

Pipeline & Schemas

5.1 Pipeline Flow

ug index

Source files → indexed-tree.json (FileNode[] + FolderNode[] + dependencies)

ug graph

indexed-tree.json → graph.json (GraphNode[] + GraphEdge[] + stats)

ug ingest

graph.json → ugdb/Neo4j (embedded nodes + edges + FTS)

One-step: ug gen runs index → graph → ingest sequentially.
Step-by-step: ug index && ug graph && ug ingest.
With viz: ug gen --serve or ug serve.

5.4 Pipeline Steps

1. Index (indexer.rs)

Discovers files with supported extensions via scan_files(). For each file: tree-sitter parse → symbol extraction → import/export resolution. Supported languages: Rust, TypeScript/TSX, JavaScript, Python, Java, Markdown, PDF, Office docs. Cache: blake3 content hashes in cache.json. Output: indexed-tree.json.

2. Graph (graph.rs)

Reads IndexResult. Creates folder nodes → file nodes → symbol nodes. Resolves cross-file imports (path joins, extension permutations, basename fallback). Creates edges: Calls, Extends, Implements, References, Contains, Imports, Exports, Requires, Uses, DependsOn. Output: graph.json.

3. Ingest (storage/ingest.rs)

Reads GraphData, builds embedding text for each node (name + signature + docstring + related names + folder context + source snippet). Generates sparse keyword vectors. Incremental: diffs incoming vs stored nodes by content hash. Embeds only new/changed nodes in batches. Upserts nodes + edges to all configured backends. Output: embedded nodes and edges in ugdb/ or Neo4j.
